# 01 · 架构总览

## 1. 项目定位

`Jev-as-Controller` 是在 [VideoJev](https://github.com/MCG-NJU/VideoJev)（上游 `timejev/` 训练与评测工具链）之上做的**实验型仓库**，研究主题只有一个：

> 把 4B 的 **VideoJev-4B** 当成「候选答案评分器」，去修正 35B 的 **Qwen3.6-35B-A3B** 的候选答案分布，再取 argmax。

因此仓库里同时存在两种东西：

| 类别 | 说明 |
| --- | --- |
| **上游继承** | `timejev/`、`videojev_hf/`、`configs/`、`docs/DATA.md`、`docs/EVALUATION.md`、`docs/CHECKPOINTS.md`、`studio/`、`runtime/`——即「训练 VideoJev / 导出 HF 包 / 跑官方 7 个 benchmark」的全套能力 |
| **本仓库新增** | `scripts/*longvideobench*`、`timejev/lvb_experiment.py`、`docs/LVB_*.md`、`docs/results/`——即「LongVideoBench 分层子集 + 双模型融合 + 随机选边对照 + 结果封存」的实验流水线 |

**边界要记住**：公开结果都是「验证集子集 + 视觉 token 预算 24576（小于论文的 262144×80%）」的实验，不是 VideoJev 论文的完整官方评测；且训练/验证是否重叠未核实。

## 2. 顶层目录

| 路径 | 层次 | 作用 |
| --- | --- | --- |
| `videojev_hf/` | 发布包 | 可直接 `AutoModel.from_pretrained(..., trust_remote_code=True)` 的推理实现（config / modeling / processing / video / moe / temporal） |
| `timejev/` | 核心库 | 训练模型、数据管线、RGB 采样、时序解码、7 个 benchmark 的严格计分器、LVB 实验框架 |
| `scripts/` | 入口 | 抽样、逐模型评测、融合、汇总、训练、导出（每个都是独立 CLI，输出目录不可覆盖） |
| `configs/` | 配置 | DeepSpeed（zero2/zero3）、两阶段训练（head_only / joint）、`qa_evaluation.json` 评测注册表、qwen36/rgb192 变体 |
| `runtime/qwen36/` | 运行时 | 35B MoE 的 grouped-GEMM + CUTLASS SM89 补丁源码与构建说明（`.deps-qwen36` 被 gitignore，需按此重建） |
| `docs/` | 文档/结果 | 上游训练与评测说明 + LVB 协议说明 + 已发布结果摘要（不含权重/视频/逐题输出） |
| `tests/` | 测试 | 48 个文件；多数只依赖 CPU + 假数据，可在无权重机器上跑 |
| `studio/` | Demo | Gradio 应用：上传 ≤30s 视频，做 temporal grounding / QA |
| `sitecustomize.py`、`requirements*.txt` | 环境 | 依赖清单与运行时补丁（CUDA 栈需另装） |

## 3. 分层调用关系

```text
                        ┌───────────────────────────────────────────────┐
   CLI 层 scripts/*.py  │ sample_* / eval_* / summarize_* / evaluate* / train* / export_hf │
                        └───────────────────────┬───────────────────────┘
                                                │ import
                        ┌───────────────────────▼───────────────────────┐
   实验与计分层 timejev/ │ lvb_experiment（LVB 实验框架） / hf_evaluation（HF 统一评测） │
                        │ benchmark / qa_benchmark / videomme / mlvu / longvideobench │
                        │ rgb_media / rgb_data / video / temporal / decision_inputs   │
                        └───────────────────────┬───────────────────────┘
                                                │ AutoModel / 自定义 model
                        ┌───────────────────────▼───────────────────────┐
   推理层 videojev_hf/  │ VideoJevForVideoUnderstanding（Qwen3.5 / Qwen3.5-MoE + 决策头） │
                        └───────────────────────────────────────────────┘
   训练层（另一条线）    │ timejev/model.py(TimeJev + PointerHead) + losses/packing/deepspeed │
```

**关键设计选择**：评测是「清单驱动（manifest-driven）」而不是「benchmark 名驱动」。所有逐模型评测脚本都只吃一个 JSONL 清单 + 若干协议参数，因此**换数据集主要是换清单**，不是换代码（细节见 [03](03-其他benchmark测试建议.md)）。

## 4. 协议常量（实验可复现的关键）

| 常量 | 值 | 出处 |
| --- | --- | --- |
| QA 上下文 | `262144` | `timejev/qa_eval_settings.py: QA_CONTEXT` |
| QA 采样 | `2.0` 或 `4.0` FPS，帧上限 `2048` | `qa_eval_settings.FPS_CHOICES` / `max_frames` |
| LVB 实验默认 | `--fps 2 --max-frames 2048 --context 262144 --visual-token-budget 24576 --memory-fraction .9` | `timejev/lvb_experiment.py: evaluation_parser` |
| 空间几何 | 预算内取最大原生网格，单帧面积 ≤ 409600 px，最小边 1024 | `lvb_experiment.prepare_record` + `rgb_data.geometries` |
| 帧采样 | 均匀覆盖整段视频；超上限时仍覆盖全长 | `protocol(): frame_sampling='uniform_full_video'` |
| 模态 | 只用原始视频；`use_subtitles=False, use_audio=False`（代码强制两基线一致） | `protocol()` / `controller.read_source` |
| 融合权重 | `β = 2`，评测前固定 | `eval_longvideobench_controller.py` |
| 定位（grounding）协议 | 4 FPS、147456 tokens、阈值 0.25 | `hf_evaluation.main` 默认 `--grounding-context 147456 --threshold .25` |

## 5. 数据与产物格式

### 5.1 输入：manifest JSONL（一行一题）

```jsonl
{"id":"longvideobench/1234","question_id":"1234","video_key":"longvideobench/vid-001",
 "video_path":"videos/vid-001.mp4","duration":523.4,"task":"choice",
 "query":"What does the person do after ...","options":["A. ...","B. ...","C. ..."],
 "answer_index":2,"duration_group":600}
```

字段要求（由 `timejev/user_data.py: load_manifest` + `decision_inputs.validate_row` + `lvb_experiment.load_sample` 三层校验）：

- 必有：`id`、`video_key`、`video_path`（相对清单文件）、`query`、`duration`（秒，>0）；`task` 默认 `grounding`。
- 选择题：`options`（≥2 条，纯文本，禁止含 `<|`）、`answer_index`（0 基）。
- 同一视频的多题必须用同一 `video_key`，且 `video_path`/`duration` 一致。
- LVB 实验额外强制：`duration_group ∈ {15, 60, 600, 3600}`、`task == 'choice'`、`media_source.kind`（若存在）必须是 `video`。
- 官方严格计分器额外需要 `question_id`（LVB / Video-MME / MLVU）或 `uid`（LVBench）；MLVU 还要 `task_type`、`official_duration`。

### 5.2 输出：每个方法一个目录

```text
<out>/
  run.json          # identity：方法名、清单 SHA256、逐权重文件 SHA256、协议、设置、seed、
                    # 每个视频的字节数/mtime/SHA256、python 包版本、代码 SHA256、git HEAD + diff
  predictions.jsonl # 一行一题：probabilities / answer_index / 审计字段（首 token、几何、计时…）
  metrics.json      # 总分 + 按时长组
  runtime.json      # wall_seconds 范围说明 + 显存峰值
  source/           # 关键源码快照 + git.diff
```

Qwen 行额外有 `candidate_logits`、`candidate_token_ids`、`first_token_*`（审计首 token 是否裸字母）；VideoJev 行有候选内 softmax `probabilities`；Controller 行有 `qwen_probabilities`、`videojev_probabilities`、`beta` 和融合后的 `probabilities`。

**这些产物是全链路可核验的**：`Experiment` 拒绝写入非空目录；`--resume` 只有在清单/媒体/权重/代码/依赖/设置指纹**全部一致**时才允许续跑；Controller 会重算两份 baseline 的 metrics 并比对存档值。

## 6. Controller 的数据流

```text
sample_longvideobench[_proportional].py
        │  产出 sample.jsonl（+ .meta.json：seed、配额、来源 SHA）
        ├──────────────┐
        ▼              ▼
eval_longvideobench_qwen36.py        eval_longvideobench_videojev.py
（6×RTX4090，BF16，无量化）            （单卡，VideoJev-4B）
候选字母首 token logits z            候选内 softmax 概率 F_s
        └──────┬───────┘
               ▼
eval_longvideobench_controller.py（纯 CPU，不再加载模型）
    校验：清单 SHA 相同、protocol 字典完全相同、逐视频 preprocessing 完全相同
    π₁ = softmax(z + β·F_s)，β=2
               ▼
summarize_longvideobench_proportional.py
    → results.json / results.md / random_trials.jsonl（随机选边 50 次、OR 上界）
```

三个容易忽略的语义：

1. Qwen 的概率只在**该题真实候选字母内**归一化，不是全词表概率；即使首 token 不是裸字母，也按预定义候选 logits 计分，不剔除题目。
2. `F_s` 直接用 VideoJev 的候选概率，**不取 log、不再 softmax**。
3. 融合不需要 GPU，因此换 β、换统计口径可以零成本重跑。

## 7. 模块职责速查

### 7.1 `videojev_hf/`（发布 / 推理）

| 文件 | 职责 |
| --- | --- |
| `configuration_videojev.py` | `model_type = "videojev"`，包装 `backbone_config`（Qwen3.5 / Qwen3.5-MoE）+ `decoder` 阈值 |
| `modeling_videojev.py` | 主干最后一层改为 attention-only + `CosineDecisionHead`；`encode_video`（分块视觉编码）、`predict_video`（原视频→答案）、`predict_features`（视觉特征→答案，评测主入口） |
| `processing_videojev.py` | 视频/查询分组预处理、`format_predictions` |
| `videojev_video.py` / `videojev_temporal.py` | 帧采样、两帧一组的时间线与区间解码 |
| `videojev_moe.py` | FP32 router、XTuner grouped experts 安装 |

### 7.2 `timejev/`（按用途分组）

| 组 | 模块 | 说明 |

## 8. 代码里的硬约束（改东西前先读这里）

| 约束 | 位置 | 后果 |
| --- | --- | --- |
| 输出目录必须为空 | `Experiment.__init__`、`controller.evaluate` | 直接抛错，不会覆盖 |
| 两模型协议必须逐字段相等 | `controller.read_source` | fps/frames/context/budget/几何/无字幕音频任一不同即失败 |
| 逐视频 preprocessing 必须相同 | `controller.evaluate` | 保证同一时间线、同一几何才可融合 |
| Qwen logits 与候选内 softmax 概率必须自洽 | `controller.control`（`math.isclose`） | 防止把已 softmax 的值再当 logits |
| 概率和为 1、answer_index 必须是 argmax | `lvb_experiment.validate_prediction` | 越界/非有限值即中断 |
| 35B 评测必须用已编译的 SM89 grouped-GEMM 后端 | `eval_longvideobench_qwen36.load_backend` | 缺 `.deps-qwen36` / `.deps-xtuner` / `reports/setup-qwen36-runtime/sm89-cutlass.patch` 就报错；**不允许降级** |
| 官方 benchmark 必须全量 | `qa_eval_settings`、各 `*_benchmark.COUNTS` | 少一题就拒绝计分 |

## 9. 与上游 VideoJev 的关系

- `docs/DATA.md`（JSONL + 两阶段训练）、`docs/EVALUATION.md`（7 benchmark 评测）、`docs/CHECKPOINTS.md`（HF 导出）讲的是**上游能力**，本仓库保留可用。
- `README.md` 讲的是**本仓库的实验**：LongVideoBench 子集 + Controller + 随机选边/OR 上界。
- 两套评测路径并存：`scripts/evaluate.py`（训练 checkpoint，走特征缓存 `data/cache/<bench>_f2`）与 `scripts/evaluate_hf.py`（发布 HF 包，走原始视频 RGB）。**换 benchmark 时先确认自己走的是哪条**。
