# 迁移 Jev Docker 环境到 10.168.100.128

以下命令分别在两台 Linux 宿主机执行，不要在 Docker 容器内运行 docker。目标将仓库、data、models、runs、hf-cache 统一放在 /data2/hyj/jev；容器内仍使用 /workspace/Jev-as-Controller。源路径暂按此前已确认的容器 jev-bench-migrated-v2、仓库 /home/hyj/srv/jev/Jev-as-Controller、资产 /public/hyj/jev 编写。先用 docker inspect 核对，若源挂载已变，先改下方变量。不要更改整机 DockerRootDir，也不要清理 Docker layerdb。

## 1. 检查源与目标

源服务器宿主机：

~~~bash
sudo docker ps -a --filter name=jev-bench-migrated-v2
sudo docker inspect jev-bench-migrated-v2 \
  --format '{{.Config.Image}}{{println}}{{range .Mounts}}{{println .Source "->" .Destination}}{{end}}'
test -d /home/hyj/srv/jev/Jev-as-Controller/scripts
for d in data models runs hf-cache; do test -d "/public/hyj/jev/$d" || exit 1; done
ssh hyj@10.168.100.128 'test -d /data2/hyj/jev && test -w /data2/hyj/jev && df -hT /data2/hyj/jev && nvidia-smi -L'
~~~

目标目录若尚未由 hyj 管理，请先由目标服务器管理员创建或授权该项目目录，不要在整机的 /data2 上改变所有权。确认目标 GPU 架构与原先编译的 Qwen grouped-GEMM 后端兼容；镜像迁移不包含宿主机驱动或 NVIDIA Container Toolkit。源服务器仍在下载或评测时，等写入停止再做最终 rsync 和 docker commit。

## 2. 源服务器保存运行镜像

若容器创建后手工安装过 pip/apt 包，使用 docker commit 捕获容器可写层。它默认短暂停顿容器进程，因此应在无运行任务时执行。若能确认环境全部在现有已构建镜像内，也可对该镜像 docker tag 后直接 save。下面采用 commit，镜像名使用新的 tag，不覆盖原镜像：

~~~bash
set -euo pipefail
IMAGE=jev-bench:to128-20261106
TRANSFER=/public/hyj/jev/transfer-to128
mkdir -p "$TRANSFER"
df -hT "$TRANSFER"
sudo docker commit jev-bench-migrated-v2 "$IMAGE"
sudo docker save "$IMAGE" | gzip -1 > "$TRANSFER/jev-bench-to128.tar.gz"
(cd "$TRANSFER" && sha256sum jev-bench-to128.tar.gz > jev-bench-to128.tar.gz.sha256)
ls -lh "$TRANSFER/jev-bench-to128.tar.gz"
~~~

docker save 压缩时可能长时间不打印进度；另开终端查看归档大小即可。只有 save 命令成功返回后，才使用校验文件。docker commit 不包含 bind mount 中的代码、模型和视频，下一步必须单独复制。

## 3. 复制镜像和挂载数据

继续在源服务器宿主机执行。确认 hyj 对目标 /data2/hyj/jev 可写。保留隐藏目录和 .deps-qwen36、.deps-xtuner；不要用只复制 scripts 的方式替代仓库迁移。

~~~bash
set -euo pipefail
TARGET=hyj@10.168.100.128
DST=/data2/hyj/jev
SRC_REPO=/home/hyj/srv/jev/Jev-as-Controller
SRC_ASSETS=/public/hyj/jev
TRANSFER=/public/hyj/jev/transfer-to128

ssh "$TARGET" 'mkdir -p /data2/hyj/jev/{transfer,Jev-as-Controller,data,models,runs,hf-cache}'
rsync -a --no-owner --no-group --partial --info=progress2 \
  "$TRANSFER/jev-bench-to128.tar.gz" "$TRANSFER/jev-bench-to128.tar.gz.sha256" \
  "$TARGET:$DST/transfer/"
rsync -a --no-owner --no-group --partial --info=progress2 \
  --exclude='/data/' --exclude='/models/' --exclude='/runs/' \
  "$SRC_REPO/" "$TARGET:$DST/Jev-as-Controller/"
for d in data models runs hf-cache; do
  rsync -a --no-owner --no-group --partial --info=progress2 \
    "$SRC_ASSETS/$d/" "$TARGET:$DST/$d/"
done
~~~

若某个源目录的实际挂载路径与上面不同，以 docker inspect 结果为准修改 SRC_ASSETS 或逐项传输。rsync 中断后可重跑，不会主动删除目标现有文件。若只迁移运行环境而新服务器已有完整模型/视频，可跳过相应数据项，但需在容器创建前检查目标文件确实存在。不要带 --delete。

## 4. 目标服务器导入并创建容器

SSH 登录 10.168.100.128 后在其宿主机执行。镜像加载占用 DockerRootDir 的磁盘，而非一定占用 /data2；先检查两个位置的可用空间。若 docker load 报 layerdb 的 file exists，不要手动删 Docker 内部目录，交由管理员检查 daemon 存储状态。

~~~bash
set -euo pipefail
ROOT=/data2/hyj/jev
cd "$ROOT/transfer"
sha256sum -c jev-bench-to128.tar.gz.sha256
DOCKER_ROOT=$(sudo docker info --format '{{.DockerRootDir}}')
df -hT "$DOCKER_ROOT" "$ROOT"
sudo docker load -i jev-bench-to128.tar.gz
sudo docker image inspect jev-bench:to128-20261106 --format '{{.Id}} {{.Os}}/{{.Architecture}}'

test -f "$ROOT/Jev-as-Controller/scripts/check_bench_runtime.py" || exit 1
test -d "$ROOT/Jev-as-Controller/.deps-qwen36" || exit 1
for d in data models runs hf-cache; do test -d "$ROOT/$d" || exit 1; done
mkdir -p "$ROOT/Jev-as-Controller"/{data,models,runs}
sudo docker ps -a --filter name=jev-bench-128

sudo docker run -d --name jev-bench-128 \
  --gpus all --network host --shm-size=32g \
  --ulimit memlock=-1 --ulimit stack=67108864 \
  --mount type=bind,src="$ROOT/Jev-as-Controller",dst=/workspace/Jev-as-Controller \
  --mount type=bind,src="$ROOT/models",dst=/workspace/Jev-as-Controller/models \
  --mount type=bind,src="$ROOT/data",dst=/workspace/Jev-as-Controller/data \
  --mount type=bind,src="$ROOT/runs",dst=/workspace/Jev-as-Controller/runs \
  --mount type=bind,src="$ROOT/hf-cache",dst=/root/.cache/huggingface \
  --workdir /workspace/Jev-as-Controller \
  jev-bench:to128-20261106 tail -f /dev/null
~~~

若目标已有 jev-bench-128 容器，先检查其配置，改用新名字；不要直接覆盖或删除。网络用 --network host，但不会自动迁移旧主机的 127.0.0.1 代理。所有宿主机挂载目录应在 docker run 前存在；不要在容器运行时删除并重建这些目录。

## 5. 验收挂载、GPU 与后端

先在目标宿主机检查 Docker 记录的实际挂载，再进入容器：

~~~bash
sudo docker inspect jev-bench-128 \
  --format '{{range .Mounts}}{{println .Source "->" .Destination}}{{end}}'
sudo docker exec -it jev-bench-128 bash
~~~

以下在目标容器内部：

~~~bash
cd /workspace/Jev-as-Controller
findmnt -T data
findmnt -T models
find data/benchmarks -maxdepth 1 -mindepth 1 -type d -print
ls models
nvidia-smi
python -m pip check
python - <<'PY'
import torch
print('CUDA available:', torch.cuda.is_available())
print('GPU capabilities:', [torch.cuda.get_device_capability(i) for i in range(torch.cuda.device_count())])
PY
git config --global --add safe.directory /workspace/Jev-as-Controller
source scripts/env_qwen36.sh
python scripts/check_bench_runtime.py \
  --out "reports/bench-runtime-128-$(date +%Y%m%d-%H%M%S).json"
~~~

如果 GPU 或后端检查失败，先检查目标宿主机驱动、Container Toolkit 和 GPU 架构；不要据此删除原服务器数据，也不要直接强行跑正式评测。运行正常后可在目标容器内继续使用原来的 manifest 和 runs；模型、数据、结果均位于 /data2/hyj/jev。退出容器 shell 用 exit，宿主机上重新进入用 sudo docker exec -it jev-bench-128 bash。
