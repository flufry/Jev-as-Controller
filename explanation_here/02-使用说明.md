# 02 · 使用说明

按「最小可跑通」的顺序组织：环境 → 模型/数据 → 复现 LVB 实验 → 用 HF 评测跑其他 benchmark → 训练/导出 → 测试 → 坑位清单。

> 所有命令都在**仓库根目录**、且先激活虚拟环境后执行。`scripts/env.sh` 只导出环境变量，不激活 venv。

## 1. 环境

实际实验环境（README 记录）：Python 3.12.12、PyTorch 2.8.0+cu128、torchvision 0.23.0+cu128、Triton 3.4.0、transformers 5.14.1、accelerate 1.15.0、FlashAttention 2.8.3.post2、causal-conv1d 1.7.0、av 18.1.0。用 `uv` 管理：

```bash
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890
export ALL_PROXY=http://127.0.0.1:7890
export http_proxy="$HTTP_PROXY" https_proxy="$HTTPS_PROXY" all_proxy="$ALL_PROXY"
export NO_PROXY=localhost,127.0.0.1,::1
export no_proxy="$NO_PROXY"

uv venv --python 3.12 .venv
source .venv/bin/activate
uv pip install --python .venv/bin/python torch==2.8.0 torchvision==0.23.0 \
  --index-url https://download.pytorch.org/whl/cu128
uv pip install --python .venv/bin/python -r requirements.txt
```

还需要与 Python/PyTorch/CUDA ABI 匹配的 **FlashAttention** 与 **causal-conv1d**（`requirements.txt` 不含完整 CUDA 栈锁文件）。

### 1.1 35B 的 grouped-GEMM 后端（跑 Qwen3.6 必做）

`scripts/eval_longvideobench_qwen36.py` 的 `load_backend()` 会硬性检查：

- `.deps-qwen36/grouped_gemm`（含已编译的 `grouped_gemm_backend`，且带 `qwen36_cutlass_only` 标记）
- grouped_gemm 源码 revision `172fada8…`、CUTLASS submodule revision `8783c418…`
- `.deps-xtuner`（revision `76e70513…`）
- `reports/setup-qwen36-runtime/sm89-cutlass.patch`（与 `runtime/qwen36/sm89-cutlass.patch` 字节相同）

缺任何一项都直接报错，不会降级成 Python 专家循环。重建步骤见 `runtime/qwen36/README.md`（面向 SM89 / CUDA 12.8 / PyTorch 2.8；其他架构需自行验证）。自检：

```bash
source .venv/bin/activate && source scripts/env_qwen36.sh
python - <<'PY'
from scripts.eval_longvideobench_qwen36 import load_backend
print(load_backend()[1])
PY
```

### 2.1 LongVideoBench（约 26.76 GiB）

```bash
hf download Jialuo21/LongVideoBench --repo-type dataset \
  --revision 0c30edb990835a4ffd48059cd84d0680c62887a3 \
  --include 'lvb_val.json' --include 'videos/*.mp4' \
  --local-dir data/benchmarks/longvideobench
```

离线转成评测清单（保留官方 `video_path`，**不要**用 `video_id + ".mp4"` 猜文件名）：

```bash
source .venv/bin/activate && source scripts/env.sh
python - <<'PY'
import json
from pathlib import Path
from timejev.longvideobench_benchmark import formatted_options, validate_reference

base = Path('data/benchmarks/longvideobench')
raw = (base / 'lvb_val.json').read_bytes()
official = json.loads(raw)
validate_reference(official)
rows = [dict(
    id='longvideobench/' + r['id'], question_id=r['id'],
    video_key='longvideobench/' + r['video_id'],
    video_path='videos/' + r['video_path'], duration=r['duration'],
    task='choice', query=r['question'], options=formatted_options(r),
    answer_index=r['correct_choice'],
) for r in official]
assert all((base / row['video_path']).is_file() for row in rows)
with (base / 'official.json').open('xb') as stream:
    stream.write(raw)
with (base / 'questions.jsonl').open('x', encoding='utf-8') as stream:
    for row in rows:
        stream.write(json.dumps(row, ensure_ascii=False, allow_nan=False) + '\n')
PY
```

注意：清单里**没有** `duration_group`，抽样脚本会从 `official.json` 补上；`validate_reference` 要求正好 1337 题 / 753 视频 / 3-4-5 选项分布（1/353/983）。

## 3. 复现 LVB 比例抽样实验（主结果）

```bash
source .venv/bin/activate && source scripts/env_qwen36.sh
export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1
LVB_RUN=runs/lvb_proportional_reproduce

for seed in 42 43 44; do
  cell="$LVB_RUN/seed$seed"
  python scripts/sample_longvideobench_proportional.py --seed "$seed" --n 100 --out "$cell/sample.jsonl"

  for protocol in baseline controller; do
    if [ "$protocol" = baseline ]; then fps=4; frames=4096; else fps=2; frames=2048; fi

    CUDA_VISIBLE_DEVICES=0,1,2,3,4,6 \
      python scripts/eval_longvideobench_qwen36.py \
      --manifest "$cell/sample.jsonl" --out "$cell/qwen_$protocol" \
      --checkpoint models/Qwen3.6-35B-A3B --seed "$seed" \
      --device cuda:0 --gpu-count 6 --max-memory-gib 18.5 \
      --fps "$fps" --max-frames "$frames" \
      --context 262144 --visual-token-budget 24576 --memory-fraction .9

    CUDA_VISIBLE_DEVICES=7 \
      python scripts/eval_longvideobench_videojev.py \
      --manifest "$cell/sample.jsonl" --out "$cell/videojev_$protocol" \
      --checkpoint models/VideoJev-4B --seed "$seed" \
      --device cuda:0 --fps "$fps" --max-frames "$frames" \
      --context 262144 --visual-token-budget 24576 --memory-fraction .9
  done

  python scripts/eval_longvideobench_proportional_controller.py \
    --manifest "$cell/sample.jsonl" --seed "$seed" \
    --qwen "$cell/qwen_controller" --videojev "$cell/videojev_controller" \
    --out "$cell/controller" --beta 2 --qwen-method qwen36

  python scripts/summarize_longvideobench_proportional.py \
    --mode single --manifest "$cell/sample.jsonl" --seed "$seed" \
    --qwen-baseline "$cell/qwen_baseline" --qwen-controller "$cell/qwen_controller" \
    --videojev-baseline "$cell/videojev_baseline" --videojev-controller "$cell/videojev_controller" \
    --controller "$cell/controller" --out "$cell/summary"
done

python scripts/summarize_longvideobench_proportional.py --mode all --base "$LVB_RUN" --out "$LVB_RUN/summary"
```

每个 seed 是 4 次模型推理 + 1 次 CPU 融合 + 1 次汇总；三 seed 合计 12 模型步 + 7 CPU 步。示例不自动调度共享 GPU，卡号要按自己机器改。

想复现「等量四时长组各 25 题」的旧口径，把抽样与 Controller 换成：

```bash
python scripts/sample_longvideobench.py --per-group 25 --seed 42 --out runs/lvb100_equal_seed42/sample.jsonl
python scripts/eval_longvideobench_controller.py --beta 2 \
  --manifest runs/lvb100_equal_seed42/sample.jsonl \
  --qwen runs/lvb100_equal_seed42/qwen --videojev runs/lvb100_equal_seed42/videojev \
  --out runs/lvb100_equal_seed42/controller
```

> 关键点：`eval_longvideobench_controller.py` 是**通用**的（吃任意符合条件的清单）；`eval_longvideobench_proportional_controller.py` 只是给它套上「LVB 比例抽样元数据 + seed∈{42,43,44} + n=100」的适配层。**换 benchmark 时用前者**。

## 4. 用 HF 评测跑官方 benchmark（只需一个模型）

`scripts/evaluate_hf.py` 直接吃发布包（本地目录或 HF repo id），不需要特征缓存，只解码原始视频：

```bash
source .venv/bin/activate && source scripts/env.sh
# 先空跑校验清单/标注，不加载权重
python scripts/evaluate_hf.py --checkpoint ZhuYuhan/VideoJev-4B \
  --benchmark all --data-root data/benchmarks --out runs/benchmarks --dry-run

# 真正评测
python scripts/evaluate_hf.py --checkpoint ZhuYuhan/VideoJev-4B \
  --benchmark videomme --data-root data/benchmarks --out runs/benchmarks
```

目录约定（每个 benchmark 一个子目录）：

```text
data/benchmarks/<name>/
  questions.jsonl        # 清单，题数必须等于官方全量
  videos/...             # 视频（路径相对清单）
  official.json          # 官方标注（lvbench 用 official.jsonl）
```

| `--benchmark` | 题数 | 指标 |
| --- | ---: | --- |
| `charades` / `activitynet` / `qvhighlights` | 3363 / 4500 / 1541 | mIoU、R1@0.3/0.5/0.7 |
| `lvbench` | 1549 | Accuracy（+ 分类） |
| `videomme` | 2700 | Accuracy（+ duration/domain） |
| `longvideobench` | 1337 | Accuracy（+ 四时长组） |
| `mlvu` | 2174 | M-Avg（7 任务宏平均） |

其它开关：`--reference <path>` 换官方标注路径、`--plans <dir>` 用已规划的 `evaluation_<context>.json` RGB 计划、`--threshold` 改 grounding 阈值、`torchrun --nproc-per-node=N` 让每张卡独立吃整段视频。

自定数据（无官方标注也能跑，指标退化为通用 choice accuracy）：

```bash
python scripts/evaluate_hf.py --checkpoint ZhuYuhan/VideoJev-4B \
  --manifest /path/to/eval.jsonl --out runs/eval_custom
```

产物：`predictions.jsonl`、`metrics.json`、`summary.json`（QA 全齐时还会写 `qa_results.json` / `RESULTS.md`）。

> 说明：这条路径只产出 **F_s（VideoJev 单模型）** 的分数，不产出 Controller。要做 Controller 见 [03](03-其他benchmark测试建议.md)。

## 5. 训练与导出（上游能力，按需）

```bash
python scripts/prepare_data.py --manifest /path/to/train.jsonl --base /path/to/Qwen3.5-4B \
  --out data/custom4b --world-size 8
torchrun --standalone --nproc-per-node=8 scripts/train.py \
  --config data/custom4b/configs/head_only.json --out runs/custom4b/head_only
torchrun --standalone --nproc-per-node=8 scripts/train.py \
  --config data/custom4b/configs/joint.json --out runs/custom4b/joint \
  --init-head runs/custom4b/head_only/head.pt
# 导出成可发布 HF 包
python scripts/export_hf.py --checkpoint <final/checkpoint> --base <匹配的 Qwen 目录> \
  --out <new/HF-model> --expected-id <ID> --expected-sha256 <SHA256>
```

35B 用 `--model-size 35B-A3B` + `scripts/train_qwen36.py`；多机用 `scripts/cluster_*.sh` 里的 rendezvous 参数。详见 `docs/DATA.md`、`docs/CHECKPOINTS.md`。

## 7. 坑位清单

| 现象 | 原因/对策 |
| --- | --- |
| `FileExistsError: 选择新的输出目录` | 所有评测/融合都拒绝复用非空目录；换目录，或对**同一条命令**加 `--resume` 且指纹一致 |
| `输出已存在或恢复指纹不一致` | `--resume` 只有在清单/媒体/权重/代码/依赖/设置全一致时才允许 |
| `两基线的评估协议不完全一致` | 两份 baseline 的 `--fps/--max-frames/--context/--visual-token-budget` 必须完全一致 |
| `缺少 .deps-qwen36 的已编译 grouped GEMM` | 没按 `runtime/qwen36/README.md` 重建后端 |
| `需要官方、未量化的 Qwen3.6 Qwen3_5Moe checkpoint` | 35B 脚本拒绝量化/offload；且 `--gpu-count` 只能 4/5/6 |
| `可见 GPU 数量少于指定的完整层分布卡数` | `CUDA_VISIBLE_DEVICES` 里卡数要 ≥ `--gpu-count`；`--device` 只能是逻辑 `cuda:0` |
| 联网超时/反复请求 HF | 评测脚本内部已设 `HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1`；下载时才需要代理 |
| 样本量看起来对不上 | 抽样脚本的 `--seed` 必须同时传给两个模型（`--seed`），否则 `Experiment` 指纹不同、无法融合 |
| `完整视频及问题超出上下文预算` | 2048 帧 / 24576 视觉 token 的上限；调 `--visual-token-budget` 或降 `--max-frames`（两模型必须一致） |
| 想一键跑全流程 | `scripts/run_longvideobench_*`、`launch_*`、`recover_*` 依赖本机历史 `runs/`/pilot 文件，**不是**新 checkout 的入口 |

## 8. 结果怎么读

- 单个方法目录：`metrics.json` 里的 `accuracy` / `by_duration_group`（LVB）或 `by_duration` / `by_task`（Video-MME / MLVU）。
- 三 seed 汇总：`summary/results.json`、`results.md`、`random_trials.jsonl`；均值与**样本方差**（ddof=1，单位：百分点²）。
- 随机选边（`Qwen + VideoJev` 50% 随机）与 OR 上界（用标签，不可作为方法）是两个对照口径，别混用。
- 只跑 3 个 seed 不能宣称统计显著；两种抽样口径的均值也不能直接比较。
