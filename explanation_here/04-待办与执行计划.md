# 04 · 待办与执行计划：同方法迁移到其余视频 benchmark（粗筛口径）

> 适用范围：**沿用 Jev-as-Controller 现有方法**（Qwen 候选 logits + VideoJev 候选概率，β=2），在其余视频选择题 benchmark 上做**小样本粗筛**，判断「方向对不对、哪里增益大」，**不跑全量、不追 SOTA 数字**。LongVideoBench 现有子集结果保持不变，不再追加全量。

---

## 0. 目标 / 非目标

| | 内容 |
| --- | --- |
| **目标** | 每个新 benchmark 上用 ~150 题粗筛，回答 3 个问题：(a) Controller 相对同协议 Qwen 基线是正是负；(b) 增益天花板（OR 上界）有多大；(c) 增益是否集中在长视频 / 时序类任务 |
| **非目标** | 全量 2700/2174/1549、统计显著性结论、与论文/榜单数字对齐、4 FPS 算力对齐基线、新 benchmark 上的调参（β 固定 2） |
| **复用** | 两个逐模型评测脚本 + 通用融合脚本 **原样使用**（不改现有文件）；只新增清单构建、抽样、汇总三类脚本 |
| **口径** | 2 FPS / 最多 2048 帧 / context 262144 / 视觉 token 24576 / 无字幕无音频 / β=2 / 两模型协议必须逐字相同 |

## 1. 选哪些 benchmark、每份抽多少题

| Benchmark | 总量 | 粗筛样本 | 分层方式 | 为什么选 |
| --- | ---: | ---: | --- | --- |
| **Video-MME** | 2700 | **150**（short/medium/long 各 50） | 官方三档等量 | 时长跨度最宽，直接检验「视频越长、小模型评分器越有用」 |
| **MLVU-Dev**（仅 MCQ） | 2174 | **140**（7 任务各 20） | 7 个 task_type 等量 | 官方指标是宏平均 M-Avg，等量抽样才与官方口径同构 |
| **LVBench** | 1549 | **150** | 按官方 question_type 类别比例（最大余数法） | 超长视频（多有 >1h），是最容易翻车也最有说服力的一档 |

不选：LongVideoBench（已有子集结果，本次不再动）、EgoSchema / LongVideoBench-test（标签不公开）、任何需要字幕才能公平比较的赛道。

**抽样规则（三个 bench 统一）**

- 抽样单位 = 问题；同一视频可被抽中部分题（与 LVB 现有做法一致）。
- 固定 seed（先 42；只有当结论贴着阈值时再补 43），算法用整数最大余数法分配配额。
- 保留原始题序、选项顺序、标签；输出 `sample.jsonl` + `sample.meta.json`（记录来源 SHA、配额、选中 ID 列表、样本 SHA）。
- 不按答案或模型表现选题；不在粗筛样本上调 β。

## 2. 需要新增的代码（都不改现有文件）

> 原则与 `eval_longvideobench_proportional_controller.py` 相同：**运行时打补丁 + 薄封装**，避免动 `timejev/lvb_experiment.py`，否则会影响已有 LVB 结果的可复现性。

| # | 新增文件 | 作用 | 关键要点 |
| --- | --- | --- | --- |
| **T1** | `scripts/build_bench_manifest.py` | 官方标注 → `questions.jsonl`（videomme / mlvu / lvbench 三个适配器） | 每个适配器末尾调用对应的 `validate_reference`；**每行显式写 `media_source`**（见风险 R2） |
| **T2** | `scripts/sample_bench_subset.py` | 分层粗筛抽样 | 复用 `sample_longvideobench_proportional.allocate_counts` 的最大余数逻辑；meta 里写 `source_sha256 / quotas / selected_ids / sample_sha256` |
| **T3** | `scripts/bench_compat.py` | 兼容层：把 `lvb_experiment` 的 `load_sample` / `score` 换成通用版本 | `lvb_experiment.load_sample = generic_load_sample`、`lvb_experiment.score = generic_score`；通用 `score` 按 `stratum`（回退 `duration_group`）分组 |
| **T4** | `scripts/eval_bench_qwen36.py` / `eval_bench_videojev.py` / `eval_bench_controller.py` | 三个薄封装：先 `bench_compat.install()`，再调用现有 `main()` | 保证 `run.json` 指纹、断点、逐题校验行为完全一致 |
| **T5** | `scripts/summarize_bench.py` | 通用汇总：三方法 + 随机选边（50 次）+ OR 上界 + 异答统计 + 分层表 + β 扫描 + bootstrap CI + McNemar | 逻辑照抄 `summarize_longvideobench_proportional.py` 与 `simulate_longvideobench_random_choice.py`，去掉 LVB 抽样元数据校验 |
| **T6**（可选） | `scripts/report_bench_screen.py` | 把三个 bench 的粗筛结果合成一张 md/JSON 总表 | 只读 `summary/results.json` |

### T3 为什么必须存在

`timejev/lvb_experiment.load_sample()` 强制 `duration_group ∈ {15, 60, 600, 3600}`，`score()` 按该字段分组。新 benchmark 没有这个字段，直接跑会在第一步抛错。两种解法：

- **推荐**：`bench_compat` 里换成 `generic_load_sample`（只要求非空选择题）+ `generic_score`（按任意 `stratum` 字符串分组）。
- 备选：清单里把时长映射进四档（Video-MME：short→60 / medium→600 / long→3600）。零代码，但报表语义变成"分档"，且 MLVU 没有时长分档可用。

## 4. 判定阈值（粗筛只用来做方向判断）

| 指标 | 含义 | 阈值 | 动作 |
| --- | --- | ---: | --- |
| **OR 上界 − Qwen(2fps)** | 方法的天花板 | **< 1.0 pp** | 该 bench 无空间，**放弃**（先排查清单/协议实现错误再放弃） |
| **异答率** | 两模型答案不同的题目占比 | **< 5%** | 同上，融合几乎无从下手 |
| **Controller − Qwen(2fps)** | 主效应 | **≥ +2 pp 且 > 0** | 方向成立，记录；是否加 seed / 全量另议 |
| | | **−2 ~ +2 pp** | 不确定；优先看 OR 上界与分层（长视频档是否为正） |
| | | **≤ −2 pp** | 反向证据：先跑 β 扫描（1/2/3），仍为负则如实记录 |
| **长视频档 vs 短视频档** | 假设检验 | 长档 Δ > 短档 Δ | 支持「时序/长视频增益」假设，可作为主叙事 |
| **β 敏感性** | 稳定性 | β∈{1,2,3} 结论方向一致 | 一致才可写入结论 |

**必须同时声明的限制**：n≈150 时 95% CI 约 ±7–9 pp，粗筛**不能**声称显著性；随机选边与 OR 上界的方差远小于准确率差，所以决策主要看这两个指标，而不是 Δ 本身。

---

## 5. 预算估算

先跑 1 个 bench 实测，再外推：

- **Qwen3.6-35B-A3B**：每题一次完整前向（2048 帧、24576 视觉 token），时间随卡数变化；`predictions.jsonl` 里每题有 `timing.question_inference_seconds`，`run.json`/`runtime.json` 有墙钟。粗筛 150 题 ≈ (单题时间 × 150) + (视频数 × 预处理时间)。同视频多题共享一次预处理，但每题一次前向。
- **VideoJev-4B**：按视频分组，`timing.video_group_total_seconds` 已包含预处理 + 编码 + 同组全部题目，通常 1 卡数十分钟量级。
- **融合/汇总/β 扫描/CI**：CPU，秒级–分钟级，可任意重跑。
- 三个 bench × 2 个模型 ≈ 6 个模型步 + 3 个融合步；按 1 个 bench 的实测时间线性外推即可估总时长。

## 9. 与「全量」路线的关系（备查）

本计划的结论只支持"方向性判断"。若某个 bench 上 `Controller − Qwen ≥ +2 pp` 且 OR 上界充裕，再决定是否升级为全量；升级时需要额外准备：

- 汇总脚本换成"无抽样"版本（现有两个 summarizer 都写死 `n=100 / per_group=25`）；
- 统计口径从"3 seed 方差"换成"配对 McNemar + bootstrap CI"（全量无抽样方差）；
- 预算按粗筛实测线性放大到 2700 / 2174 / 1549 题。
